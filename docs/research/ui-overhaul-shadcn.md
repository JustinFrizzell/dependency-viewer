# Shadcn design and asset research

Research for [#27](https://github.com/JustinFrizzell/dependency-viewer/issues/27), 2026-11-26. This is a design reference, not a component-library or framework decision. No production code is changed.

## Bottom line

Use shadcn's semantic tokens, restrained surfaces and component patterns as references for the graph-first prototypes. Start with this application's existing TypeScript, DOM and CSS; do not assume that a shadcn React component can be dropped into it. If actual assets or source are later adopted, inventory their individual licenses, maintain notices, and verify offline, accessibility and build behavior. The prototypes and subsequent wayfinding tickets still decide layout, interaction and implementation.

## Existing application constraints

At research baseline [`bc5b571`](https://github.com/JustinFrizzell/dependency-viewer/tree/bc5b5716e958b08e6939de3371fce8101f3eb5ab), [`package.json`](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/package.json) lists TypeScript, webpack, Cytoscape and CSS loaders, but no React or Tailwind. [`src/index.ts`](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/src/index.ts) directly manipulates the DOM; [`src/style.css`](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/src/style.css) is ordinary CSS. The [TypeScript config](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/tsconfig.json) includes `.ts`, not `.tsx`, and the [webpack config](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/webpack.config.ts) processes `.ts` and CSS.

The [README](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/README.md) specifies a self-contained HTML file opened directly, Node 24+ for building, and third-party notices embedded in the HTML. The [browser tests](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/test/browser/offline.test.ts) exercise `file://` offline and assert no external requests. Any future fonts, icons, scripts and styles must preserve that contract; do not rely on a CDN or runtime font fetch.

## Design and reusable references

- [Shadcn's introduction](https://ui.shadcn.com/docs) describes editable component source, composable APIs and consistent defaults, rather than a conventional install-and-import component library. Its [theming guide](https://ui.shadcn.com/docs/theming) uses semantic surface/foreground pairs, border, input and ring tokens, with `.dark` overrides. The **concept** maps naturally to hand-written CSS variables: separate graph background, panel, selected/hover/focus and destructive states; test both themes rather than assuming default values fit a graph.
- [Sheet](https://ui.shadcn.com/docs/components/radix/sheet) is a dialog-derived complementary surface with configurable edges. It is a useful visual reference for entity details, but a graph-anchored, persistently interactive inspector is not automatically a modal sheet. [Radix Dialog](https://www.radix-ui.com/primitives/docs/components/dialog) defaults to modal and traps focus; modal content makes the graph inert. Prefer a non-modal inspector pattern when graph and details must remain usable together, and test focus movement and return. Save modal/alert dialog patterns for genuinely interrupting actions; the [WAI modal pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) describes naming, focus, Escape and inertness requirements.
- [Command](https://ui.shadcn.com/docs/components/radix/command) illustrates grouped search/quick actions and uses the separate `cmdk` component. It may inform entity search and navigation, not replace existing search semantics. [Sidebar](https://ui.shadcn.com/docs/components/radix/sidebar), [button](https://ui.shadcn.com/docs/components/radix/button), [tabs](https://ui.shadcn.com/docs/components/radix/tabs), [field](https://ui.shadcn.com/docs/components/radix/field) and [popover](https://ui.shadcn.com/docs/components/radix/popover) are references for shell, modes, forms and contextual actions. Their suitability for graph-editing remains a prototype question, not a mandate to use them.
- [Tooltip](https://ui.shadcn.com/docs/components/radix/tooltip) describes supplemental information on focus or hover. Do not make it the sole route to entity details: keyboard, touch and persistent selection must work independently. [Lucide](https://lucide.dev/guide/lucide) supplies SVG icons and a vanilla-JavaScript package, so it is a candidate without adopting React; use a small selection and verify actual bundle output. Its [accessibility guide](https://lucide.dev/guide/lucide/advanced/accessibility) recommends labeling icon-only buttons on the button, with decorative icons hidden from assistive technology.
- Check text, focus/selection indicators, nodes and edges in both themes against [WCAG text contrast](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) and [non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html): generally 4.5:1 for normal text and 3:1 for necessary UI-state and graphical information, subject to the criteria's exceptions. Color must not be the only indication of interaction or graph meaning.

## Adoption paths and trade-offs

1. **Visual inspiration only (recommended for the prototypes):** reproduce needed layout and behavior with local HTML/CSS/TypeScript. Semantic variables and familiar control patterns need no framework migration. Implementation still owns keyboard, touch, screen-reader, contrast and focus behavior; looking like a component does not confer its accessibility.
2. **Selectively reuse assets:** local SVGs or the vanilla Lucide package can coexist with the current stack, subject to provenance, notices, size and offline verification. Do not assume icons, fonts or third-party examples inherit the shadcn repository license.
3. **Copy actual shadcn components:** the [manual setup](https://ui.shadcn.com/docs/installation/manual) uses Tailwind, aliases, helper dependencies and TSX; the [Sheet example](https://ui.shadcn.com/docs/components/radix/sheet) uses React-style components and the Radix dialog. This project would need deliberate React/React DOM integration, TSX/typecheck and webpack changes, Tailwind processing, aliases, component-specific primitive packages and lifecycle coordination with the existing Cytoscape/DOM code. Verify dependencies and generated output for the exact chosen version. Copying source transfers maintenance of that source and upgrades to this project. A larger rewrite is not justified by visual inspiration alone.

The [registry](https://ui.shadcn.com/docs/registry) distribution format can support any framework; that does **not** make the official React component implementations framework-independent. [Installation](https://ui.shadcn.com/docs/installation) lists framework templates and manual setup, not an existing vanilla-TypeScript/webpack drop-in guide. Evaluate non-React or community registry items individually rather than assuming equivalence or compatibility.

## Licensing and attribution checklist

- The [shadcn/ui repository license](https://github.com/shadcn-ui/ui/blob/main/LICENSE.md) is MIT, copyright 2023 shadcn: copying substantial source requires retaining its copyright and permission notice. Record the exact upstream file, revision and any modifications; include the applicable notice with distributed copies, including the standalone HTML via this project's existing notices mechanism. This is practical guidance, not legal advice.
- [Radix primitives](https://github.com/radix-ui/primitives/blob/main/LICENSE) are separately MIT-licensed, copyright WorkOS. A copied shadcn component can bring independent dependencies (for example Radix or `cmdk`); inspect the precise packages and transitive licenses for the selected versions, not just shadcn's license. Update [`THIRD_PARTY_NOTICES.txt`](https://github.com/JustinFrizzell/dependency-viewer/blob/bc5b5716e958b08e6939de3371fce8101f3eb5ab/THIRD_PARTY_NOTICES.txt) and confirm notices survive bundling.
- [Lucide's license](https://lucide.dev/license) is ISC and requires its copyright and permission notice in copies. It explicitly lists Feather-derived icons with an additional MIT notice for Cole Bemis; preserve the relevant notices when using those icons. Check the exact release and assets used.
- The [official Figma page](https://ui.shadcn.com/docs/figma) lists community-contributed free and paid kits, maintained by their respective creators. “Free” or listed there does not establish a uniform license or redistribution right: check each specific file's terms and embedded assets before copying, sharing or bundling. Similarly verify font and community registry licenses separately; no Figma asset or font is adopted by this research.

## Before any production adoption

Record chosen assets, upstream version, license and modifications; update notices and embedded output. Prototype graph selection, non-modal details, mode safeguards and keyboard/touch access before picking primitives. Confirm focus visibility and contrast, accessible names and navigation, then run the existing typecheck/build and offline browser suite with networking disabled. Measure resulting HTML size and confirm no runtime network requests or lost editing/export behavior. These are proposed validation gates, not results from an implementation.
